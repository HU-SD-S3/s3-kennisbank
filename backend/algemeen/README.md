# Algemene development vaardigheden

Eigenlijk hoort dit allemaal net zo goed bij frontend, maar het staat nu toevallig even hier...

* We zeggen dat we [kwaliteits-software](./structurele-kwaliteit) willen schrijven? Wat betekent dat eigenlijk?
* We werken bijna overal met [Object Georienteerde](./object-orientatie) talen, maar wat is dat eigenlijk?
* Goed weten wat OOP is, is noodzakelijk, maar wat zijn wat meer praktische handvaten? We noemen [Domain-Driven Design (DDD)](./ddd) als voorbeeld
* Hoe horen we een applicatie eigenlijk [in te delen](./componenten-lagen)?

En als dit algemene development vaardigheden zijn [waarom staat dit dan bij Backend?](./koppeling-frontend)
